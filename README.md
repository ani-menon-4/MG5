# MG5
## Devlog
1. I feel that it's better to use movement via NavMesh when you want a GameObject to autonomously to a specific destination while avoiding paths crossing over potential areas that are not desirable, whereas physics movement would be better for a character that might need to factor collision into movement. As an example, an NPC simulating a vehicle might want to only path on terrain with a road label, so that would be an advantageous situation for the Navmesh system. On the other hand, if this NPC needed to factor into hitting a wall or another vehicle, they might need to use physics based movement in order to handle that collision.
2. The loop first creates a reference to a bird within the _birds array at the particular index specified, then checks to if the distance between the position of the bird and player exceeds a certain constant defined by a member variable in BirdManager by using Vector3's Distance() method. From here, if this check returns true, then the bird referenced will execute the RunAway() method with the player's Vector3 position as an argument, causing it to retreat from the player's current position. With this loop's inclusion in the Update() method, this makes it so that the loop will run through every bird included in the BirdManager every frame and check whether any given bird is close enough to the player, at which point it will run away until the check next frame, where it will run the check again to ensure if it should continue fleeing. Therefore, any bird within the _birds array that is close enough to the player at any given frame will begin to run away.
